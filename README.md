# Практика 4.1: Асинхронность и состояния UI (Имитация сети)

**Время на выполнение:** 90 минут  
**Цель:** Научиться переводить синхронный код на асинхронный, использовать `async/await` и внедрить паттерн состояний (`AsyncState<T>`) для управления интерфейсом во время загрузки данных.

>   **Важно:** В этой практике мы **не используем реальный интернет**. Мы будем имитировать задержки и сбои сети с помощью `Promise` и `setTimeout`, сохраняя данные в `localStorage`. Это позволит нам сфокусироваться на логике `async/await` и обработке ошибок, не отвлекаясь на проблемы CORS или недоступности внешних API.

## Задание 1. Создаем слой имитации сети (20 мин)

Создайте новый файл `src/mock-api.ts`. Его задача — читать и писать в `localStorage`, но **асинхронно**, имитируя поход на сервер.

**Требования:**

1. Напишите функцию `delay(ms: number)`, которая возвращает `Promise<void>` и резолвится через `setTimeout`. *(Подсказка: см. Слайд 15 лекции)*.

   ```typescript
   function delay(ms: number): Promise<void> {
     return new Promise(resolve => setTimeout(resolve, ms));
   }
   ```

2. Напишите асинхронную функцию `async fetchBooks(): Promise<Book[]>`:
   - Ждет `await delay(800)`.
   - В 20% случаев (`Math.random() < 0.2`) выбрасывает ошибку: `throw new Error('Сбой сети. Не удалось загрузить книги.')`.
   - В остальных случаях читает данные из `localStorage` и возвращает их (или пустой массив, если там ничего нет).
3. Напишите асинхронную функцию `async saveBooks(books: Book[]): Promise<void>`:
   - Ждет `await delay(500)`.
   - Сохраняет массив в `localStorage` под ключом `'catalog'`.

## 📝 Задание 1. Паттерн состояний AsyncState (20 мин)

В файле `src/main.ts` удалите стартовую синхронную отрисовку. Вместо неё введите единое состояние приложения.

**Требования:**

1. Опишите тип состояния (можно в `task1-types.ts` или в начале `main.ts`):

   ```typescript
   type AsyncState<T> =
     | { status: 'idle' }
     | { status: 'loading' }
     | { status: 'success', data: T }
     | { status: 'error', message: string };
   ```

2. Создайте переменную: `let state: AsyncState<Book[]> = { status: 'loading' };`
3. Напишите функцию `render()`, которая использует `switch (state.status)`:
   - `'idle'`: показывает начальный UI.
   - `'loading'`: очищает контейнер и показывает текст или спиннер «Загрузка данных...».
   - `'success'`: вызывает вашу существующую логику отрисовки списка книг, передавая ей `state.data`.
   - `'error'`: показывает красный блок с текстом `state.message` и кнопкой «Повторить попытку».

> **Золотое правило (Слайд 29 лекции 6):** После *каждого* изменения переменной `state` вы должны вызывать функцию `render()`, иначе интерфейс не обновится.

## Задание 3. Асинхронная инициализация (15 мин)

**Требования:**

1. Напишите `async function initApp()`.
2. Внутри используйте блок `try...catch`:
   - Сначала установите `state = { status: 'loading' }` и вызовите `render()`.
   - Попробуйте получить данные: `const books = await fetchBooks()`.
   - Если успех: `state = { status: 'success', data: books }`.
   - Если ошибка (в блоке `catch`): `state = { status: 'error', message: error instanceof Error ? error.message : 'Неизвестная ошибка' }`.
3. В конце функции вызовите `render()`.
4. Запустите `initApp()` при загрузке страницы.

**Проверка:** Обновите страницу. Вы должны увидеть индикатор загрузки минимум на 0.8 секунды. Если вам «не повезет» (сработает 20% шанс ошибки), вы увидите экран ошибки.

## Задание 4. Асинхронные действия пользователя (20 мин)

Теперь нужно перевести добавление и удаление книг на асинхронный лад, не ломая текущий интерфейс.

**Требования:**

1. Сделайте обработчик формы асинхронным *(Подсказка: см. Слайд 30 лекции)*:

   ```typescript
   form.addEventListener('submit', async (e) => {
     e.preventDefault();
     // ... ваша логика
   });
   ```

2. При сабмите формы:
   - Проверьте, что `state.status === 'success'`, и возьмите текущие книги из `state.data`.
   - Создайте новый массив с добавленной книгой.
   - Вызовите `await saveBooks(newBooksArray)`.
   - Если успех: обновите `state = { status: 'success', data: newBooksArray }` и вызовите `render()`.
3. **Обработка ошибок сохранения** *(Слайд 31 лекции)*: если `saveBooks` упал, **не меняйте** `state.status` на `'error'` (иначе список книг исчезнет с экрана). Вместо этого используйте отдельную переменную `let errorMessage = ''`, запишите туда текст ошибки и вызовите `render()` (который покажет временное сообщение рядом с формой). Через 3 секунды очистите `errorMessage` и снова вызовите `render()`.

##  Советы
1. **Не делайте сам класс `BookCatalog` асинхронным.** Модель данных должна работать с памятью мгновенно и синхронно. Асинхронным должен быть только *слой взаимодействия с внешним миром* (наш `mock-api.ts`) и *функции инициализации и обработчики событий* в `main.ts`.
2. **Типизация ошибок.** Помните, что в строгом режиме TypeScript переменная `error` в блоке `catch` имеет тип `unknown`. Всегда используйте проверку `if (error instanceof Error)`, прежде чем читать `error.message`.
3. **Тестирование ошибок.** Чтобы гарантированно увидеть экран ошибки и отладить его верстку, временно измените условие в `fetchBooks` на `if (Math.random() < 1.0)`. Не забудьте вернуть `0.2` перед сдачей работы!
